# Tranlithion 字幕翻译

一个 **Manifest V3 Chrome 扩展**：在 YouTube、Netflix 与 Google Meet 网页上已显示、可访问的文本字幕上同步叠加译文。

优先级是**观看稳定性和上下文一致性**，而不是把所有视频都强行转写。它不会绕过 DRM、站点访问限制或版权保护，不处理烧录字幕，也不捕获任何音频。

## 当前能力

- 优先读取 `HTMLVideoElement.textTracks` 的字幕轨道。
- 在 YouTube 上回退读取已显示的 `.ytp-caption-segment` 文本字幕。
- 在 Netflix 上回退读取已显示的公共字幕 DOM（如 `data-uia="player-subtitle-text"`）；不读取媒体请求、加密流或播放器内部数据。
- 在 Google Meet 上读取会议自带字幕（见「会议模式」）：带说话人、按墙钟计时、不读音频。
- 语言对为 **日语 / 英语 / 简体中文三向互译**，源语言与目标语言在设置页各自选择。
- 统一为带起止时间的 `SubtitleCue`，避免同一句反复提交翻译。
- 双轨字幕：可选先由更快的通道立即上屏「草稿」（带下划线标记），主翻译服务返回后自动替换为正式译文。草稿通道可选 Chrome 内置本地翻译、DeepL API 或自定义 HTTP 机器翻译服务。草稿只会被更完整的结果覆盖，晚到的草稿不会把已定稿的字幕改回低质量文本；通道不可用时自动跳过，不影响原有流程。
- 字幕的结束判定跟随播放进度（`video.currentTime`）而非墙钟时间或 DOM 空白状态，因此暂停、倍速与拖动进度条时字幕行为与画面一致。
- 译文在其字幕结束后仍会短暂保留，避免因译文比原文晚到而被压缩掉阅读时间；下一句字幕出现时立即让位。
- 后台按观看会话串行翻译，携带近期 8 句上下文、用户术语表和已识别的人物名线索。术语表放在请求的 system 前缀中，使其在会话内保持稳定、便于服务端缓存命中。
- 使用 `chrome.storage.session` 保持当前会话上下文，即使 Manifest V3 Service Worker 休眠后也可恢复；页面离开时清理。
- 支持 OpenAI 兼容 Chat Completions API、自建 WebSocket，或清晰标记的离线演示模式。
- 视频 Overlay 支持中文主字幕、双语、字号、位置和背景不透明度设置；翻译开启时会视觉隐藏 YouTube 原生字幕以避免重叠，暂停后立即恢复。
- API Key 只存在当前 Chrome 配置文件中受信任扩展上下文可访问的存储区域，永远不会发送给视频网站或内容脚本。

## 架构

```text
YouTube / Netflix / Google Meet 文本字幕 / TextTrack
  → SubtitleCue 标准化（可带 speaker）
  → 时钟源：视频页用 video.currentTime，会议页用墙钟
  → Manifest V3 Background Translation Agent
      ├─ 最近上下文（含说话人）
      ├─ 术语和人物名记忆（会议中自动登记发言人姓名）
      ├─ 文本级译文缓存（重复句即时命中）
      └─ 单会话顺序 / 最新优先队列
  → 译文 Overlay（Netflix / Meet：粘性更新，会话内隐藏原生字幕）
```

## 本地开发

要求：Node.js 20+、Chrome 或 Chromium。

```bash
npm install
npm run verify
```

构建产物位于 `dist/`。在 Chrome 中加载：

1. 打开 `chrome://extensions`。
2. 打开“开发者模式”。
3. 选择“加载已解压的扩展程序”。
4. 选择本仓库的 `dist` 目录。
5. 固定 `Tranlithion 字幕翻译`，然后打开扩展设置。

开发时可运行：

```bash
npm run dev
```

它会监听 TypeScript/CSS 修改并更新 `dist/`；在 `chrome://extensions` 点击扩展的刷新按钮即可重新加载。

## 配置翻译服务

### OpenAI 兼容 API

在扩展设置页填写：

- API 地址，例如 `https://api.openai.com/v1`
- 模型，例如 `gpt-4.1-mini`
- 你的 API Key

点击“保存并测试「こんにちは」”时，Chrome 会请求连接该服务域名的可选网站权限。接受前请核对域名。

> API Key 以明文保存在 Chrome 的扩展存储中；扩展会将本地与会话存储限制为 `TRUSTED_CONTEXTS`，从而不向内容脚本开放读取权限。请使用专用、可撤销且权限最小化的 Key；不要把它同步到不受信任的 Chrome 配置文件。

### 自建 WebSocket

选择“自定义 WebSocket”后，服务应接受：

```json
{
  "type": "translate",
  "requestId": "uuid",
  "sourceLanguage": "ja",
  "targetLanguage": "zh-CN",
  "cue": { "id": "…", "text": "こんにちは" },
  "context": [{ "source": "…", "translation": "…" }],
  "terminology": [{ "source": "五条悟", "target": "五条悟", "kind": "name" }]
}
```

并返回：

```json
{
  "requestId": "uuid",
  "translation": "你好。",
  "entities": [{ "source": "五条悟", "target": "五条悟", "kind": "name" }]
}
```

`requestId` 必须原样返回；服务端错误可通过 `error` 字段返回。

## 在 Netflix 测试

不需要新增翻译服务配置：沿用已验证的 API Key 即可。更新扩展后：

1. 在 `chrome://extensions` 为 Tranlithion 点击“重新加载”。
2. 打开网页版 `https://www.netflix.com`，登录后播放内容。
3. 在 Netflix 播放器中选择与扩展**源语言设置一致**的字幕（默认为日文）；不要选择目标语言的字幕作为输入。
4. 等待当前字幕出现。扩展会读取该页面上已显示的文本，并以中文 Overlay 替换视觉显示；暂停扩展会恢复 Netflix 原字幕。

**Netflix 显示策略（防闪 / 贴近实时）：**

- 翻译开启后，原生日文字幕在整段会话内保持视觉隐藏（`opacity: 0`），句与句之间**不会**闪回日文。
- Overlay 采用粘性更新：新一句到来时**不**清空中文；上一句中文留在屏上，直到本句草稿 / 流式 / 终稿就绪后再原地替换。
- 相同日文台词会命中文本级缓存（content 本地 + background 会话），重复句可即时上屏，无需再等网络往返。
- 流式 token 有轻量节流，避免逐字重绘造成字幕抖动。

Netflix 字幕会先等待约 **60 毫秒**的文本稳定期，再发送翻译；连续变化中的旧字幕请求会被取消，只保留最新一句。因此正常等待时间约为“稳定期 + 你的翻译服务响应时间”（缓存命中则为稳定期本身），而不是前面多句字幕的累计时间。开启草稿字幕后，草稿通道的译文会先行上屏，之后由主翻译服务的结果替换。翻译服务失败或超时会显示“翻译服务不可用”；若此时草稿或上一句中文已在屏幕上，则保留可读译文并在扩展弹窗中说明，不会把可读的译文换成错误提示。

字幕的出现与消失使用不同的判定，且消失以**播放进度**而非墙钟时间为准。新文本等待约 60 毫秒即提交翻译；而容器读到空白**不作为该句结束的依据**——Netflix 会在重绘同一句字幕时短暂清空容器，把第一次空白当作结束会导致字幕反复隐藏再出现。真正的结束条件是：容器持续为空，且 `video.currentTime` 相对该句最后一次可见时已前进约 **1200 毫秒**。播放器若用新的 DOM 节点重挂同一行字幕，适配器会识别相同文案并继续当前句，而不会先 end 再 start。

以播放进度计时使字幕行为与画面一致：暂停时 `currentTime` 不前进，译文保持在屏；倍速播放时保持时长按比例缩短；拖动进度条（前进或后退）会立即结束当前句。译文在其字幕结束后的保留时间同样以播放进度计算。

Netflix 适配仅作用于页面已经公开给浏览器 DOM 的字幕文本。它不会绕过 DRM、读取加密媒体流、下载字幕或捕获受保护音频。若弹窗显示“未检测到可读取的字幕”，请确认已开启日文字幕；若仍无效，说明该播放器版本没有向页面暴露可读取文本，需要等待兼容性更新。

## 会议模式（Google Meet 网页版）

在 `https://meet.google.com` 上读取 **Meet 自己已经开启并渲染出来的字幕文本**，按发言人把译文叠在页面底部。

**不做的事**（与影视路径同一条边界）：不使用麦克风、不捕获标签页或系统音频、不做 ASR、不接入任何会议 SDK、不录制会议。Meet 没开字幕时扩展会直说读不到，不会伪造译文。

### 启用步骤

1. 打开扩展设置页，在「会议模式」中勾选**在 Google Meet 上开启会议字幕翻译**。
2. 点击**授权并启用 meet.google.com**。Meet 是**可选**网站权限：Chrome 会显示该域名请你确认，授权前扩展不会读取任何会议页面。授权后内容脚本才会注册，请刷新会议页面。
3. 在 Meet 底部工具栏点击**开启字幕（CC）**，并把 Meet 的字幕语言设为你在扩展里选的**源语言**。
4. 保存设置（会议译文通道所需的域名授权在保存时一并申请）。

### 译文通道（默认走便宜的一跳）

一小时会议的句数是一集剧的数倍，所以默认**不**走大模型：

| 选项 | 行为 |
| --- | --- |
| **机器翻译通道**（默认） | 使用「草稿翻译」里配置的通道（Chrome 内置本地翻译 / DeepL / 自定义 HTTP）直接作为**正式译文**上屏，只有一次网络往返，不再等大模型。 |
| **本机 LibreTranslate** | 走本机 `localMtUrl`，会议文本不离开这台电脑。需同时勾选「启用本机 LibreTranslate」。 |
| **大模型主译** | 按影视模式：草稿先上屏、主模型返回后覆盖。质量最好，成本与延迟也最高。 |

通道没配好时扩展**不会**偷偷改用大模型，而是显示「会议翻译通道尚未配置」并停在那里——避免在你明确选了便宜通道的情况下产生一小时的大模型账单。

同一条快路径在 Netflix 上也存在：草稿通道选 DeepL 且已填 Key 时，DeepL 结果直接作为终稿，不再等主模型。

### 时序与显示

- **墙钟计时、非视频锚点**：Meet 有多个参与者小窗、没有能代表会话的单一 `video`，所以会议模式用 `performance.now()` 计时，Overlay 锚在视口而不是某个 `<video>` 上。
- **说话人**：`SubtitleCue.speaker` 可选。说话人单独一行显示，不会混进被翻译的正文，但会作为上下文交给翻译服务。**说话人切换即结束当前句**并开新句。
- **ASR 修订**：语音识别每几百毫秒重写一次同一行，且会改掉已经显示的词。适配器只提交**尚未提交过的增量**，并在句末标点处切段；控制器对会议源使用 400 ms 去抖（Netflix 为 100 ms），使一句话大致对应一次翻译请求。识别器完全不给标点时，按词边界在 160 字符处强制切段，避免同一段落被反复整段重译。
- **空白不等于结束**：Meet 会在两次识别更新之间清空字幕条。真正的结束条件是字幕区**持续为空 1.6 秒**（墙钟），或换了发言人。
- **粘性 Overlay**：会话内隐藏 Meet 自带字幕条（`opacity: 0`，文本仍可读取），新一句到来时不清空上一句译文，直到新译文就绪再原地替换。
- **共享屏幕一键隐藏**：扩展弹窗在 Meet 标签页上会出现「隐藏译文（共享屏幕）」开关；打开后立刻不显示译文、**也不再发送任何会议文本**，Meet 自带字幕同时恢复。设置页也有同一开关。
- **吉祥物默认关闭**：会议页常被共享出去，3D 精灵默认不出现；需要时在设置页单独打开。

### 术语与人名

会议模式复用既有的术语表与会话实体记忆：

- 会前把与会人姓名和项目术语贴进设置页的**术语与人物名**（一行一个 `原文 = 译文`，人名前加 `@`）。它们放在请求的 system 前缀里，同一场会议内保持稳定、便于服务端缓存命中。
- 会议进行中，Meet 给出的**发言人姓名会自动登记为人名实体**，使同一场会议内的称呼一致；会话结束即清除。
- 同一场会议里重复出现的整句会命中文本级缓存，后面的相同句子无需再等网络往返。

完整的可检索词典 UI 不在本轮范围内。

### 本机会议记录与隐私（默认保留 7 天）

- 勾选「在本机保存会议双语记录」后，**已定稿**的双语行会写入 `chrome.storage.local`。只存在这台电脑的扩展存储中，**不上传、不同步**。
- 保留时长默认 **7 天**，可选 1 / 7 / 30 天；过期记录在扩展启动和每次写入时自动删除。最多保留 20 场会议、每场 2000 行。
- 设置页的「会议文本的去向」会根据当前通道**明确写出会议内容会发送到哪个服务**（或不离开本机），并提供「立即清除全部会议记录」。
- 打开「隐藏译文」时不发送任何会议文本，也不写记录。

导出（`.txt` / `.srt`）与多站点（Zoom / Teams / 腾讯会议）属于后续里程碑。

### 兼容性风险

Meet 的字幕节点是混淆类名。适配器优先使用语义选择器（`[role="region"][aria-label*="aption" i]`、`aria-label` 含「字幕」），再回退到已知类名，最后回退到「头像 + 姓名 + 正文」的行结构；三层都失配时会如实报告「未检测到 Meet 字幕」。Meet 改版后可能需要更新 `src/content/adapters/meet-caption-adapter.ts` 中的选择器，对应夹具测试见 `tests/meet-caption.test.ts`。

## 已知范围与下一步

- 当前支持桌面网页版 YouTube、Netflix 与 Google Meet。Netflix 仅匹配 `www.netflix.com` 与 `netflix.com`；Meet 仅匹配 `meet.google.com`，且是需要用户单独授权的**可选**站点权限。
- 语言对为日语 / 英语 / 简体中文三向互译，在设置页各自选择；源语言与目标语言相同时会被自动纠正。源语言**自动检测**尚未实现。
- 仅处理网页可读取的文本字幕；OCR 烧录字幕、标签页音频捕获、麦克风、VAD 和流式 ASR 都不在范围内，会议模式同样不涉及任何音频。
- 草稿通道选择 Chrome 内置翻译时依赖 Translator API。该 API 是否向内容脚本所在的隔离环境暴露、以及所选语言对是否可用，随 Chrome 版本与设备而变，**尚未在真实 Netflix / Meet 页面上确认**。不可用时草稿通道会静默关闭；此时可改用 DeepL、自定义机器翻译或本机 LibreTranslate。
- 会议记录目前只在本机保存与自动过期，**没有导出 UI**；`.txt` / `.srt` 导出、Zoom / Teams / 腾讯会议适配、可检索词典 UI 属于后续里程碑。
- 已验证一条人工日语字幕轨道、Netflix DOM 适配夹具、Meet 字幕 DOM 夹具和全屏路径；真实网站兼容性仍应在更多人工/自动生成字幕、播放器与 Meet 版本、不同地区内容、布局和网络条件下回归测试。
